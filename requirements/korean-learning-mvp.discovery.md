# Korean Learning MVP Discovery

## Problem Statement

用户想做一款用于学习韩语的产品，学习内容主要来自两类真实语境：

- K-Pop 歌曲歌词
- 韩剧台词

当前 MVP 的核心不是课程体系、社交功能或长期学习记录，而是让用户打开应用后立刻进入学习状态，通过一个个词条快速学习韩语单词及其语境出处。

## Goals

- 提供一个极简的韩语学习 MVP，打开后直接开始学习单词。
- 每个学习页面只展示三个核心信息：
  - 韩语单词
  - 中文翻译
  - 单词出处，来源于 K-Pop 歌词或韩剧台词
- 用户点击“下一个”后进入下一个单词。
- 整体体验偏移动端、内容优先、低干扰。

## Non-Goals

- 不做登录、注册、游客身份管理。
- 不做收藏、点赞、分享。
- 不做学习进度记录、已学状态、连续学习天数。
- 不做搜索、筛选、分类导航作为 MVP 必需功能。
- 不做复杂音频播放、视频播放、字幕同步。
- 不做后台管理系统或内容上传系统。

## Target Users and Scenarios

- 对韩语感兴趣、希望通过流行文化内容入门的用户。
- 喜欢 K-Pop 或韩剧，希望在熟悉语境中记忆单词的用户。
- 典型场景：
  - 用户打开应用，立刻看到一个韩语词条。
  - 用户查看中文含义和出处，理解这个词在真实内容中的使用方式。
  - 用户点击“下一个”，继续浏览下一个词条。

## Constraints

- Technical
  - 当前仓库几乎为空，MVP 需要从零搭建。
  - 已确认前端技术栈采用 `Vite + React + TypeScript`。
  - 首版应优先使用本地静态数据或 mock 数据，避免引入后端依赖。
  - 界面应以移动端优先实现。
  - 首批正式词条与出处数据目前尚未提供，不能把自动生成内容直接视为最终产品数据。

- Product
  - MVP 必须足够轻，核心链路只有“展示词条 -> 点击下一个 -> 展示下一个词条”。
  - 内容来源限定在 K-Pop 歌词与韩剧台词语境。
  - 当前 Figma 设计包含启动页与分类入口页，但这与“打开后直接开始学习”存在范围冲突。

- Timeline
  - 先完成可演示的 MVP，不扩展长期学习体系。
  - 优先保证核心流程闭环，而不是一次性覆盖完整产品形态。

## Assumptions

- MVP 以移动端 Web App 形态实现，而不是原生 iOS/Android 应用。
- MVP 保留 Figma 中的 3 个页面：启动页、学习页、分类页。
- 用户从启动页进入学习体验，不经过登录。
- 学习页一次只展示一个单词条目。
- “出处”字段可以用简洁文本表示，例如歌曲名/剧名及上下文来源。
- 首版数据由前端内置的静态数组提供，但数据来源仍需明确是用户提供的正式内容还是仅用于演示的 mock 数据。
- 分类页在 MVP 中作为可浏览页面存在，但不引入复杂筛选逻辑。

## Acceptance Criteria

- 打开应用后，用户无需登录，可先看到启动页，并能进入学习页。
- 当前词条页面必须同时展示：
  - 韩语单词
  - 中文翻译
  - K-Pop 或韩剧中的出处
- 页面中存在明确的“下一个”操作入口。
- 用户点击“下一个”后，会切换到下一条词条内容。
- MVP 包含 3 个页面/界面状态：启动页、学习页、分类页。
- 首版不出现登录、收藏、学习记录、完成状态等功能入口。
- 页面在移动端宽度下可正常阅读和操作。

## Open Questions

- 首批词条数据是否由你直接提供？如果不是，是否允许先用明确标注为 demo/mock 的占位数据完成界面和交互？
- “出处”字段是否只展示来源名称，还是需要附带一句简短原句/歌词片段？
- 首批 MVP 需要内置多少个示例词条，是否需要同时覆盖 K-Pop 与韩剧两类来源？
